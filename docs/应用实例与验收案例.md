# 应用实例与验收案例

整理日期：2026-11-08。功能定义与实现状态见 [通用功能需求](需求核查与待办.md)；本文件保存需求来源、现象和验收案例，不作为按软件分割的功能待办。

案例中出现的软件名、安装布局、端口和报错只描述当时的环境。进入其他机器后重新取证；适配负责提供差异信息，共享功能负责诊断与操作。未记录实际结果的内容是待验收要求，不是已发生事实。

0.6.0 本轮已将既有应用检查、诊断、预览应用和验证放入同一画布流程。未知普通应用、浏览器和第二种合成后台的隔离测试证明共享机制可复用；真实软件后台仍须有明确适配，以下未验收业务不会自动改为通过。0.6.0 成品已通过隔离验收，F07 健康观察及 F08 请求分析等完全未实现能力暂缓开发。

## C01 · 系统代理已开，但应用的独立后台仍无法访问目标

- **实例：** Hermes 开 TUN 能使用模型，关 TUN 仅开系统代理不能使用；给 Setup 设置代理不覆盖已安装应用的模型后台。
- **功能映射：** F01 软件/入口识别、F02 配置范围与进程关系、F04 应用生命周期、F05 诊断、F10 交互。
- **同类结构：** GUI 与独立后台分离的桌面工具、由服务执行请求的下载器、使用不同网络库的辅助进程；这些是验收样例类型，不宣称当前均已适配。
- **现有证据与实现：** 0.5.0 实现 Windows 原生 checkout 布局的 `hermes_adapter.py`，区分 Setup/CLI/GUI，检查 default 后台身份、环境和活动任务，再按官方命令应用。0.6.0 将身份、环境、任务与生命周期差异收进内置能力适配，由 `app_connections.py` 共享检查、预览与执行后校验；不是把该安装布局推广到所有后台。自定义 home、未知后台格式、profile 私有覆盖及局域网主机名仍有边界。
- **验收要求：** 同一流程既覆盖有后台也覆盖无后台的程序；不能仅依据 GUI 代理、进程存活或后台 ready 判断业务成功。旧窗口重建旧环境、后台还有任务、身份变化均需处理。
- **反例：** 环境已经一致但目标授权失败、私有配置覆盖或服务不健康时，不应继续归因为“缺代理变量”。
- **结果状态：** 隔离 HTTP 客户端、环境与生命周期逻辑有测试；0.6.0 另以无后台普通应用和第二种合成后台验证共享流程、保护与失败分支。画布验证与“原软件已正常 / 仍然失败”反馈分开。另一台电脑实际模型回复及长期稳定性未验收；用户曾反馈安装请求能用，不等于后续模型链路完成验证。

## C02 · 安装或下载长时间没有可见进展

- **实例：** Hermes 安装中下载、Python 依赖和“安装命令及桌面”阶段很慢；截图停留在准备 Node 依赖。
- **功能映射：** F02 主/子进程关系、F05 原因判断、F06 日志与事件、F07 进展/停滞诊断。
- **同类结构：** 多阶段安装器、包管理器、构建工具、更新器。
- **现有证据与实现：** 启动环境已有 Electron 下载器兼容设置；没有安装步骤/速度/等待原因监测。日志发现当前按通用和已知路径查找，未专门覆盖 Hermes home 的 logs；用户提供的目录应作为可登记来源的实例，不应只再硬编码一个路径就关闭 F06。
- **验收要求：** 对下载仍有流量、计算仍在进行、等待输入、子进程退出和真正无进展分别提供证据。支持轮转、自定义数据目录、无适配但可手动登记的日志来源。
- **反例：** 无日志输出不一定卡死；HEAD 请求成功不能证明大文件吞吐、完整安装或依赖解析成功。
- **结果状态：** 下载器兼容已实现；通用安装/任务停滞诊断未实现。截图中的耗时不是当前机器持续状态。

## C03 · 重启短暂恢复，之后后台连接又断开

- **实例：** Hermes 出现 `service_state_unknown`、gateway inaccessible、session controls unavailable，重启后暂时恢复。
- **功能映射：** F04 生命周期、F05 诊断流程、F06 时间线、F07 健康与恢复评估。
- **同类结构：** 使用本地服务、WebSocket 或长连接的桌面应用。
- **现有证据与实现：** 按需身份/代理环境检查与受限后台应用已接入四步共享流程，可在验证后记录仍失败的用户反馈；没有持续健康监测或掉线原因时间线。系统代理回退守护不负责应用健康。
- **验收要求：** 区分进程退出、状态文件过期、服务未就绪、连接断开、远端访问失败；对重试/重启的适用条件及任务影响给出解释。记录观察时段和复测结果，不保证“重启一次后不会复发”。
- **反例：** 进程和环境均正常但业务会话失败；旧状态文件对应已复用 PID；活动任务未结束。都不能无条件重启。
- **结果状态：** 通用持续观察与恢复评估未交付；旧问题的长期根因与复发条件未完成验收。

## C04 · 启动器、游戏、加速器和代理共同作用

- **实例：** VRChat 世界/头像加载慢；旧机曾有用户代理变量残留且同时观察到 UU/Xray 相关连接。目标新电脑未找到同样三项变量。
- **功能映射：** F01 能力分类、F02 配置/继承关系、F03 接入范围、F05 诊断、F06 连接/日志关联、F07 进展观察。
- **同类结构：** 由启动器启动、继承旧环境或同时受代理/VPN/加速器影响的软件。流程以故障应用为起点，再按证据追溯实际启动器，而不是固定先查 Steam。
- **现有证据与实现：** 通用清单、TCP 快照、进程代理变量检查可用，0.6.0 可从所选软件进入检查、诊断、预览应用和验证；无合适公开地址时可留空，不强行选择测试站点。没有启动关系与日志的完整关联。无 VRChat 专用识别/日志适配是覆盖缺口，不应据此另建专用诊断引擎。
- **验收要求：** 同一流程覆盖有残留环境和没有残留环境的机器；标明用户/机器/进程变量的区别。清除新进程环境不修改已运行的启动器，也不证明绕过私有代理或 TUN。原应用加载作为业务复测。
- **反例：** 新机器没找到变量；内容首次下载体积较大；节点/缓存变化；UU 驱动路径与普通 TCP 快照不同。均不能直接套用旧机原因。
- **结果状态：** 对话中旧机清理后加载恢复是用户反馈，未完全排除其他因素；0.6.0 的未知普通应用流程已有隔离测试，但新机原因、VRChat 实际路径和加载结果未验证。

## C05 · 已识别网络工具，但无法选作出口或拖入画布

- **实例：** 新电脑识别 v2rayN，但只看到 Xray TCP 10808，没有 HTTP 卡片；UU、ZeroTier 等卡片也不能拖入。
- **功能映射：** F01 发现/能力确认、F03 接入支持、F10 交互。
- **现有证据与实现：** 0.5.1 已补所有已识别工具的点击/键盘/拖入与屏外定位，未知协议可做本机 HTTP CONNECT 检测；v2rayN 外置数据配置引用得到有限支持。工具识别与协议实测分开。
- **验收要求：** 已知代理、未知协议、纯 SOCKS、无监听、专用隧道卡片用同一能力呈现；改端口、换核心、无配置权限时不猜测。未知工具可说明已观测信息，不能自动把常见端口当 HTTP。
- **反例：** UU/aTrust/ZeroTier 的专用端口不是通用 HTTP；能在本机转发不证明远端网站可用。
- **结果状态：** 本机检测和合成界面事件通过；用户新电脑真实拖放、实际外网请求仍待验收。

## C06 · 分流规则看不懂，连线和实际生效混淆

- **实例：** Steam 卡片中的“域名规则 1”、HTTP 上游和 DIRECT 术语难理解；社区与内容下载希望使用不同连接方式。
- **功能映射：** F03 规则与接入、F05 复测、F10 可理解交互。
- **同类结构：** 任意软件按目标区分访问方式，用户需要理解规则优先级及生效范围。
- **现有证据与实现：** 已显示具体网站、范围和出口，规则/入口/应用实际使用分层。Steam 下载域名模板仅是起点；没有事件可能是软件未采用入口，而非规则正常。
- **验收要求：** 相同规则编辑与状态解释适用于不同软件；根域/子域、顺序、其他网站、未应用草稿均可理解。业务流量与规则匹配需独立验证。
- **反例：** DIRECT 仍可能经过 TUN；HTTP 成功不证明游戏下载使用该路径；新 CDN 未包含在模板中。
- **结果状态：** 规则解释与逻辑测试已有；真实浏览器易用性、Steam 完整下载路径未验收。

## C07 · 想看到实际请求和响应，而不只看设置

- **实例：** 用户要求集成 Fiddler（曾写作 fidder）相关功能，之后询问入口。
- **功能映射：** F08 请求/会话分析，结合 F05 诊断、F06 来源关联、F10 交互。
- **需求含义：** 以通用请求观察与分析能力定义交付；Fiddler 是参照，尚未确定采用该产品或库。HTTPS 解密、正文、修改/重放、HAR 等子能力分别记录范围，不将推测的完整功能集冒充用户已经逐项确认的规格。
- **验收要求：** 来自不同应用的可观察请求使用同一会话界面；未进入观察范围、加密不可见、无法确认发起者时如实显示。选定子能力后再逐项验收。
- **结果状态：** 尚未实现，无对应入口，本轮暂缓。当前活动列表、日志或探测不是这项能力的替代交付。

## C08 · 换电脑、更新或改变路径后，希望继续快捷使用

- **实例：** 两台电脑需反复配置应用代理，不想每次手输 launch；旧 EXE 曾出现 PKG archive 错误，新电脑端口/路径与旧机不同。
- **功能映射：** F04 快捷应用、F09 迁移/版本兼容、F10 易用性。
- **现有证据与实现：** 历史版本已有独立 EXE、中文/空格路径构建验收、持久化和桌面快捷方式；0.6.0 的 GUI 与快捷方式复用应用计划和执行检查，GUI 对普通应用也要求先预览再确认。GUI 导出不是完整数据迁移，没有自动匹配新机程序/入口或 GUI 更新回滚中心。旧后台需正常退出才能用新版；新版本打包验收需独立记录。
- **验收要求：** 改变用户名、盘符、路径、端口，保留连接意图并重新确认本机绑定；失效有明确修复步骤。快捷方式与 GUI 共用规则和校验。资源管理器右键/托盘只是快捷操作的候选形式。
- **反例：** 新端口有监听但属于不同程序；复制配置后程序名相同而路径/版本不同；启动新 EXE 却复用旧后台。
- **结果状态：** 已有功能和本轮共享机制有隔离测试，跨机完整操作尚待验收。已在隔离浏览器点击验证四步流程；窄侧栏和桌面窗口已在 420、643、1366 像素宽度验收；跨机及真实拖放仍单独记录，不以合成事件替代。通用化不等于已支持自动迁移。

## C09 · DNS、隧道与系统路由改变了预期路径

- **实例：** hosts 在代理下似乎不生效、远程控制与 TUN 共存、游戏下载希望不经过代理且保留工作连接。
- **功能映射：** F02 配置层、F03 连接策略、F05 诊断、F06 路径证据。
- **现有证据与实现：** 有 hosts/路由/接口线索、精确域名解析映射和 TCP 探测；没有通用 TUN 绕过、UDP/QUIC 路径证明或完整远程会话验收。
- **验收要求：** 区分系统解析、代理远端解析、应用自有解析；显示实际可控制范围。保护其他工作连接的要求作为共享约束，不为某一应用单独实现。
- **反例：** TCP 通不等于 UDP 打洞或长期会话正常；绑定接口也不能单独证明应用绕过 TUN。
- **结果状态：** 详见历史材料和发布记录；不能将历史截图/地址当作当前机检测结果。

## C10 · 多份游戏安装共享资源与安全更新（另项目）

- **实例：** WoWS Steam/360/WG 三端共用文件，要求更新后版本管理、文件校验、隔离与回滚。
- **归属：** 游戏资源切换器。其通用需求应按多安装资源去重、版本兼容、更新事务、完整性验证及恢复组织；具体游戏/渠道是应用实例。FlowDesk 只负责其中网络连接相关的 F03/F05，不把文件管理并入代理功能。
- **验收要求：** 共享文件原地更新不损坏其他安装；版本不兼容、校验失败、更新中断时能隔离或恢复。不能从节省空间数字推断已完成。
- **结果状态：** 本次没有核对该项目当前代码和记录，保持“另项目待核查”；不认定已完成，也不认定另一项目未实现。

## 新案例记录格式
