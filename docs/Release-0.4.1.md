# 0.4.1 · 修复 Electron 下载子进程未采用代理

部分安装器收到 HTTP/HTTPS 代理环境后，主流程能够联网，但下载 Electron 的子进程仍会直连。Electron 下载器还需要专用的代理启用开关，0.4.0 的应用启动环境缺少这一项。

- “按此设置启动”和导出启动脚本统一使用同一套子进程环境策略，补充 `ELECTRON_GET_USE_PROXY=1`，并为旧版 global-agent 下载器提供对应入口、环回绕过与默认变量命名空间。
- 切到“不使用环境代理”时，清理标准代理变量及新增 Electron/global-agent 设置；“沿用默认设置”继续保留继承环境。HTTP 模式替换继承的旧入口，处理 Windows 环境变量大小写差异。
- 路由图属性和脚本模式说明标明 Electron 下载器兼容，不增加操作步骤。
- 原保存连接无需重建，目标软件正常退出后，从升级后的工作台重新启动即可应用；旧的导出脚本需要重新导出。已经运行的进程不会因升级自动改变环境。

此兼容仅作用于新进程及继承其环境的子进程。独立服务、自行过滤环境的启动器、应用私有代理及系统路由仍需实际验证；本次没有改动系统代理、TUN 或现有网络工具。

实现依据：[Electron 官方代理说明](https://www.electronjs.org/docs/latest/tutorial/installation#proxies)、[旧版 @electron/get 代理初始化](https://github.com/electron/get/blob/v3.1.0/src/proxy.ts)。
