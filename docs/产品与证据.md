# 代理接线台

把本机的应用、规则与出口画成可解释的连接图。调音台提供通道与状态，节点软件提供连接与属性，应用通道提供可复制的独立代理入口。

## 工作方式

1. 检测：读取系统代理/PAC、WinHTTP、环境变量、监听端口、进程归属、网络接口/路由/DNS/hosts。
2. 接线：每个通道的默认出口与有序域名规则可调整，预览匹配结果。
3. 运行：在环回地址启动本工具的 HTTP/CONNECT/SOCKS5 TCP 入口；仅处理实际送到这些入口的连接，不做 HTTPS 解密。
4. 接入：应用自身支持代理时填入专属端口。系统代理接入需明确应用并可回退；忽略这些设置的应用仍需其支持的独立接入方式。
5. 验证：记录 DNS、连接、TLS/HTTP 和中继事件。未知状态不会被涂成通过。

## 不做隐式动作

不重启 Codex/代理核心，不改 TUN 或默认路由，不导入节点密钥，不自动更换订阅；不强行给任意进程注入网络钩子。普通 TCP 直连仍可能经过 TUN。SOCKS UDP、QUIC 和真实 RustDesk 会话不因 TCP 检查通过就被认定成功。

## 官方实现参考

- [Microsoft：WinINet 连接选项](https://learn.microsoft.com/en-us/windows/win32/wininet/setting-and-retrieving-internet-options)：系统配置通过连接选项 API 读取和设置，避免直接覆盖注册表实现细节。
- [Microsoft：WinINet 选项标志](https://learn.microsoft.com/en-us/windows/win32/wininet/option-flags)：连接设置变更通知。

## 本轮设计修正（2026-10-24）

补入的需求是以软件为单位直观看到“在哪里设置代理、可以采用哪种控制方式、当前连接有什么证据、日志在哪里”。产品同时呈现 Windows 各层代理来源、应用接入方式与运行事实；现有 TCP 接线能力作为一种接入方式保留，逐应用流量接管可通过成熟引擎适配扩展。

本轮已找到 ProxyBridge、ProxiFyre、Proxifier 等能够处理逐应用路由与连接观察的工具，但未找到同时覆盖全部配置层、软件配置与证据定位的完整工具。调查范围、推荐定位、TCP/UDP 边界和精确官方来源见 [Windows 代理工具调查](工具调查-20261024.txt)。

界面分别标注配置值、控制应用结果、观察到的连接、内核出口关联与目标应用实测。环境变量、管理台自己的公网 IP 探测、单独的 TCP 下一跳都按各自范围展示；目标应用的实际路径需要对应证据。日志的官方默认位置和候选路径保留“待查找”状态，确认本机存在后才标为已发现，观察到写入后再标注本次活动。
