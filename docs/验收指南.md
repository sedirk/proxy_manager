# 隔离验收指南

测试应先使用临时状态目录与本机测试源。不要用正在工作的浏览器标签页或现有 Codex 连接做破坏性验证，也不要把历史材料中的端口和服务器当作本机事实。

## 自动检查

在项目目录运行：

```powershell
python -X utf8 -m unittest discover -s tests -v
node --check web/app.js
node tools/test_app_flow_ui.js
node tools/test_routing_view.js
node tools/test_manual_app_ui.js
node tools/test_guide_ui.js
```

Python 测试覆盖规则、TCP 中继、探测分层、服务边界、隐私和系统接入回退等。语法检查只证明 JavaScript 可解析；Node 检查调用实际界面事件函数，但使用合成 DOM/API，不是浏览器视觉或真实拖放验收。`test_guide_ui.js` 覆盖的是仍在代码中、主导航已隐藏的旧向导。最新重跑结果和未验证项见 [需求核查与待办](需求核查与待办.md)，历史发布结果保留在各版本说明。

## 0.6.0 共享流程验收

本轮 Python 248 项、UI 合成事件 88 项（应用流程 60、高级分流 8、手动软件 11、隐藏旧向导 9）通过；另已在隔离浏览器点击检查四步流程。打包发布、真实软件业务与跨机验收分别记录，不把这些结果合并成“全部软件可用”。420、643、1366 像素宽度的实际浏览器检查通过，覆盖折叠库、属性抽屉、画布适配和窄屏应用详情。Windows EXE 隔离验收通过，详见 [0.6.0 说明](Release-0.6.0.md)。

| 操作或样例 | 核对范围 |
| --- | --- |
| 未知普通应用、浏览器、已有后台与第二种合成后台 | 共用检查、计划、执行及验证；只按能力调用受支持操作，合成后台不算真实软件适配 |
| 不保存连线先检查、地址留空诊断 | 使用保存设置或默认基准；无目标地址不发送目标请求，不启动程序或保存设置 |
| 填写公开地址诊断 | 当前已识别入口参与路径对照；HTTP 拒绝、传输失败和成功分开，不自动归因为代理故障 |
| 采用建议 | 只放入草稿；入口失效或响应所属软件变化后，不应用旧建议 |
| 保存、预览、取消、确认 | 保存不启动；所有软件先预览；取消无副作用；设置/身份/任务变化使旧预览失效 |
| 活动任务、身份未知、旧窗口、环境不可读 | 保留已有后台保护，不能用普通应用回退绕过限制 |
| 应用进行中、部分失败与状态变化 | 拒绝发布验证或反馈；即使应用抛错也丢弃旧成功记录，需重新检查 |
| 验证与业务反馈 | 验证只用保存路径；“沿用默认设置”不伪装成直连；“原软件已正常 / 仍然失败”标为用户反馈 |
| 改变软件、连线、地址或收到延迟响应 | 结果绑定软件与当前上下文，不串到另一软件，不保留过时预览或业务反馈 |

相关测试主要位于 `tests/test_app_adapters.py`、`tests/test_app_connections.py`、`tests/test_app_workflow.py`、`tests/test_app_routes.py` 与 `tools/test_app_flow_ui.js`。服务层还校验验证记录的有效期、保存记录、应用会话和操作版本，防止应用前的检查在应用后被登记为当前证据。F07 持续监控和 F08 抓包暂缓，不能列入本轮通过项。

### 本地 API 调用兼容

- `POST /api/app-routes/launch` 对普通应用也要求 `POST /api/app-routes/prepare-launch` 返回的 `ticket`；票据一次使用、180 秒有效，绑定保存设置与预览时的软件/后台状态。调用方应先保存、预览，再带 `app_id` 与 `ticket` 确认，不能继续无票据直接启动。
- 旧 `POST /api/troubleshoot/launch`（服务方法 `guide_launch`）明确拒绝直接启动。旧向导仍隐藏；应使用应用连接的共享流程，不能绕过预览与后台保护。
- `POST /api/app-routes/diagnose` 接受 `app_id` 与可选 `url`；`verify` 使用已保存设置，忽略调用者试图覆盖的模式或入口。空地址不触发目标探测。
- `POST /api/app-routes/feedback` 接受当前验证返回的 `check_id`、同一 `app_id` 与 `outcome`（`resolved` / `failed`）。反馈记录为 `user_report`；验证记录最多有效 600 秒，保存、应用开始/结束、后续诊断/验证或所绑定的设置与应用会话变化会使其不再适用。接口仍受现有本机会话、Host 和 Origin 校验保护。
- 应用保存数据结构与桌面快捷方式入口保持兼容；快捷方式调用共享计划和执行检查，不经旧向导启动接口。它不等于自动完成业务验证。

## 应用连接的额外实机验收

以下为完整实机验收路径；本轮已完成的隔离范围见上节，未执行的真实业务和跨机项目保持待验证。普通自动化仍使用临时程序/目录与本机测试源，不启停用户应用或切换其网络设置。

| 操作 | 通过条件 |
| --- | --- |
| 添加软件、重开页面、移除登记 | 浏览/粘贴路径均可用，设置保留，无重复或删除程序副作用 |
| 拖入 v2rayN、UU、aTrust、ZeroTier | 可点击、键盘和拖入，节点在视野内；专用网络工具不误作 HTTP 出口 |
| 未知协议、仅 SOCKS、无监听、检查失败 | 明确说明下一步；只有有效 HTTP 入口能接应用，旧确认失败后不残留成功状态 |
| 画布接线、检查、诊断、预览应用与验证 | 未保存与已保存分开；所有应用先预览；检查不启动软件；目标探测、应用结果与用户业务反馈分别显示 |
| 桌面快捷方式、端口/路径变化 | 复用最新设置，失效有可理解提示；不默默选用另一台机器地址 |
| Hermes 独立后台样例 | 区分窗口与后台；身份不明、活动任务、旧窗口环境或预览过期时不重启；只确认环境/就绪，不确认模型回复 |
| 域名规则与小窗口 | 网站范围、顺序、未命中出口可读；保存/入口/真实应用状态不混淆 |

真实模型客户端、游戏或安装器的业务验收应另行安排并记录：电脑/版本、所选入口、原应用操作结果及观察时段。未执行不能用隔离测试替代。请求分析、完整进程链诊断及持续健康监测未实现，不应出现在已通过清单中。

## 通用功能与应用实例分别验收

功能使用 [需求核查](需求核查与待办.md) 中的 F 编号，应用实例使用 [案例清单](应用实例与验收案例.md) 中的 C 编号。已有特定软件适配测试属于覆盖证据，不表示整项通用功能已经完成。0.6.0 以第二种合成后台和未知普通应用验证共享机制；以下更广的功能验收仍按实现范围逐项进行，尚未实现的项不伪装为现有测试已覆盖。

| 功能 | 可复用样例 | 必须包含的反例/失败项 |
| --- | --- | --- |
| F01/F10 识别与交互 | 声明协议的代理、未知监听、只提供隧道的工具、手动登记软件 | 仅有端口不可猜协议；无适配、屏外节点或无监听仍有明确下一步 |
| F02/F04 配置范围与应用 | 单进程应用、启动器加子进程、独立后台 | 旧环境、同名不同实例、PID 变化、活动任务、缺少生命周期适配；不盲目执行重启 |
| F03 连接与分流 | 支持环境变量、显式参数及不支持这些方式的应用 | 忽略设置、未知协议、未命中规则、TUN 共存；不以连线代替接管证据 |
| F05/F06 诊断与日志 | 不同来源的日志/连接证据、用户登记来源 | 相似症状不同原因、日志轮转、路径变化、旧日志、无权限、探测成功但原业务失败 |
| F07 进展和健康 | 多阶段安装/构建、使用独立服务的长连接应用 | 缓慢但有进展、等待输入、后台退出、状态过期、信息不足；不能仅凭安静判卡死 |
| F08 请求分析 | 不同应用/隔离客户端的可观察请求 | 未进入观察范围、加密不可见、身份关联不足；子能力分别验收 |
| F09 迁移与兼容 | 不同用户名/路径/端口的两套隔离环境 | 失效适配、入口被其他程序占用、复用旧后台、旧数据格式；保留原数据 |

同一通用功能至少覆盖不同结构的两类应用或独立隔离样例，并有未知/不支持对象及相似症状不同原因的反例。可以用自建测试程序证明机制复用，无需为此启停用户生产软件。随后按案例单独记录实际业务结果，区分“适配可用”“共享机制通过”“真实业务通过”；不能只凭某个软件问题消失就标整项功能完成。

## 启动本机 UI 测试实例

```powershell
python tools/ui_fixture.py
```

实例使用临时 `.local`、环回 HTTP 测试源，不运行新一轮本机检测；若有历史检测快照，只作为展示数据读取。它明确禁止写系统代理。读取 `artifacts/ui-fixture.json` 中本次 `port` 与 `probe_url`，新开独立标签页访问 `http://127.0.0.1:port`。不要复用正常服务的标签页。

## 核心验收路径

| 操作 | 通过条件 |
| --- | --- |
| 打开页面 | 四个证据层级分开；没有把候选端口或设计连接显示为应用已正常 |
| 选择 Steam、调整规则、重新接线 | 仅草稿变化；没有修改系统、应用配置或启动任意应用 |
| 保存、导出、导入 | 通道固定端口、规则顺序、DNS 映射、notes、limits 和布局保留；导出草稿无需先保存 |
| 编辑后重新打开页面 | 不覆盖不同的本地草稿；出现恢复草稿标记；恢复服务器方案可撤销 |
| 预览 | 后端 issues 可读；有错误不能启动；影响范围明确为本地入口 |
| 启动 | 节点与属性立即刷新；显示实际入口；通道探测按钮可用，真实应用仍未知 |
| 通道探测 fixture 的 probe_url | 经过真实运行通道；精确域名映射到本机，命中 direct 规则，返回 TCP / HTTP 200 分层证据 |
| 活动事件 | connected / established 标为进行中；完成事件另列；时间正常；显示 channel_id / target_id 对应名称 |
| 从事件添加规则 | 只加入相应通道的草稿，不直接改变运行中的规则 |
| 编辑出口后探测 | 使用当前草稿出口，不误测已保存旧目标；通道探测仍明确使用运行配置 |
| 停止 | 图和属性立即退回非运行状态；实际入口停止；原代理核心不退出 |
| 探测弹窗 | 不出现“只启动本地入口”按钮；关闭后再预览可正常显示启动按钮 |

系统预览应显示原值、新值、issues、规则与 DNS 映射；`allowed=false` 时按钮始终禁用。隔离实例不应执行系统应用；真实 Windows 回退路径由专门的系统接入测试与明确的人工验收覆盖。

## 窗口与恢复

- 分别检查常规桌面、约 895 × 768 窗口及 Codex 侧栏一类更窄的浏览区域。记录实际视口；检查导航、应用选择、四步属性、表单和操作按钮可见且可操作，无不可达横向溢出。窄窗可使用抽屉或紧凑布局，但不能把文字缩到不可读；画布、属性与底部活动应能分别到达。
- 选择不同应用后检查聚焦视图能显示该通道和相关出口；切回全部节点仍能缩放、拖动、接线。不要为了适应所有节点把文字永久压缩到不可读。
- 输入属性时等待数次轮询，焦点和未提交文本应保留。停止、启动、检测变化仍需及时刷新状态。
- 服务断开后页面显示断开并尝试只读重连；重启导致令牌失效时 GET 可以刷新会话，修改请求不得自动重放。草稿继续保留。
- 生成超过 200 条事件后，后续新事件仍应出现；事件游标不能停留在最早一批。

## 真实机器的额外核对

将界面检测值与系统、v2rayN 和 UU 的实际界面对照。UU 的“加速时禁用网络代理”、hosts 冲突选项、驱动重定向和真实游戏加速会话仍需手动核对，不能由进程存在推断。

若要人工验收 WinINet 接入，先核对现有系统代理并确认当前工作连接的风险，再单独预览。验证 60 秒未确认回退、确认后手动恢复、正常停止恢复，以及其他程序修改时不强行覆盖。全过程保留原设置备份，不以强杀后台代替正常退出。

本机 HTTP fixture 通过不等于 Steam 下载、WoWS 更新、WebSocket 长连接或 RustDesk 实际会话通过。真实应用验收须另记应用是否采用入口、命中规则、实际流量及完整会话结果。
