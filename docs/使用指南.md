# 流向使用指南

适用版本：0.6.0。功能完成情况见 [通用功能需求](需求核查与待办.md)，具体故障来源见 [应用实例与验收案例](应用实例与验收案例.md)。当前没有请求分析/抓包入口、完整的进程链诊断或持续健康监控，本轮暂不扩展这些能力。以下先介绍通用操作，再列出当前适配范围内的应用示例；示例不是另一套功能需求。

## 从一个软件开始

默认进入 **路由设计** 的应用连接画布。选择软件后，右侧按 **1 检查 → 2 诊断 → 3 应用 → 4 验证** 展开处理流程。

窄窗口点击画布左上角 **软件与工具** 展开应用库；选择软件后展开属性抽屉，点关闭按钮或按 Esc 可收起。宽屏保留两侧面板。

左侧应用库列出本机软件，点击加号或拖入画布；找不到时点 **添加其他软件** 选择 `.exe`。右侧自动出现 v2rayN 等已识别的 HTTP 代理入口，以及 **沿用默认设置**、**不使用环境代理**。点击软件右侧的圆点，再点击目标节点左侧圆点即可连线。右侧属性中的“连接到”下拉框与画布表示同一设置。

1. 点 **检查此软件**，核对当前进程及已适配后台的代理环境。检查使用已保存设置；还没保存过时，以“沿用默认设置”为基准，不把尚未保存的连线当作已经生效。
2. 点 **诊断此软件**。**遇到问题的公开地址** 可留空，留空时仅检查软件，不发起目标请求；填写不含账号、令牌或查询参数的 HTTP(S) 地址后，比较工作台的默认网络路径和识别出的代理路径。可点 **查看此软件的设置与日志** 补充证据；有适用建议时，**将建议放入连线草稿** 只改变草稿。
3. 核对连接方式，点 **保存连接设置 → 预览应用步骤**。阅读将启动哪个软件、是否重配后台及限制，再点 **确认并应用**。保存不启动软件；取消预览也不会应用。普通软件的旧实例需正常退出，后台应用按适配能力检查身份和活动任务；预览后状态变化会要求重新预览。
4. 点 **验证已保存设置**，重新检查进程和已适配后台；上方有地址时，只探测保存的路径。然后回到原软件完成原操作，选择 **原软件已正常** 或 **仍然失败**。界面把这项结果标为用户反馈，工作台探测成功不会替你确认登录、模型回复或下载完成。

连线、地址或保存设置改变后，界面清除旧结果；保存及应用开始/结束也会使服务端旧验证记录失效，应用失败同样需要重新验证。验证记录限当前服务内短期使用，过期后重新验证。建议、预览和反馈都绑定所选软件，不能移用到另一个软件。

Chrome/Edge 使用浏览器显式参数；普通软件通过新进程环境设置 HTTP 代理或清除代理变量，需要软件自身支持。检查环境一致不能证明显式参数、组织策略或真实请求已生效。“不使用环境代理”不保证软件忽略私有代理、系统代理或 TUN；“沿用默认设置”由软件决定路径，工作台不会将它冒充直连来验证。

未知软件可登记并使用普通进程检查和启动方式；若请求由独立后台发送，需有相应内置适配才能管理后台。本轮是共享现有适配和流程，并未让所有未知软件的服务都能自动重配。

HTTP 代理设置还会启用 Electron 下载器兼容，处理某些安装器主进程已走代理、下载 Electron 的子进程仍直连的问题；导出脚本与画布应用使用相同配置。这项兼容从 0.4.1 起提供，当前版本保留；关闭目标软件及其安装子进程，再从工作台保存、预览并确认应用即可。兼容修正前导出的旧脚本需要重新导出。它不是下载速度或安装卡死诊断器。

### 一次设置，以后双击

软件属性中先点 **检查此软件**，查看当前进程是否采用了保存的代理。此操作只检查，不应用设置。检测记录是一个时间点的证据，不会自动等同于模型、下载或游戏正常。

选择连接方式并 **保存连接设置** 后，点击 **创建桌面快捷方式**。桌面出现 `软件名（FlowDesk）`；以后双击使用最新保存设置及共享应用检查，无需终端或 `-Launch`。后台重配仍按适配规则确认，身份不明、活动任务或旧窗口环境冲突会拒绝操作。快捷方式依赖 FlowDesk 程序与其数据目录，移动或删除后需要重新创建。它绑定当前电脑的软件路径和代理入口；在另一台电脑重新检测和保存即可。代理未响应时会提示，但快捷方式预检仅验证 TCP 可达，不能据此确认协议、监听归属或真实业务。

左侧下方列出自动识别的 v2rayN、UU、aTrust 和 ZeroTier 等网络工具。UU、aTrust、ZeroTier 的私有端口作为加速、隧道或组网依据展示，不提供可接线的通用 HTTP 入口。需要进一步查看证据时，切到 **应用与设置** 查看设置来源、日志与连接。

没有找到软件时，在 **本机软件** 标题旁点 **添加软件**。用 **浏览…** 选择 `.exe`，或粘贴完整路径，可选填显示名称，再点 **添加到清单**。添加不运行程序、不改代理；清单保存在本机，刷新和重启后仍会保留。同一路径不会重复添加。浏览窗口取消时不会产生登记；窗口无法打开时可直接粘贴路径。

在手动添加的软件详情中可 **移除手动登记**；这不会卸载软件、删除文件或关闭进程。若同一软件也被自动检测到，移除手动登记后自动发现条目仍会显示。文件已移动或删除时，清单会保留并提示路径失效，可移除后按新路径添加。

- 设置来源分别解释系统代理/PAC、WinHTTP、用户与机器环境变量、应用自身设置、TUN/路由。界面会标明观察时间和旧快照；它没有读取其他进程的完整环境。
- 日志位置区分“已发现”和“候选”。已发现资源可打开所在目录，独立的文本日志可查看脱敏尾部；配置文件只定位，不把订阅、令牌等配置内容当日志读取。发生日志轮转时重新检测再选择。
- **应用与设置中的脚本导出**生成可审查的 PowerShell 文件。直接运行导出的脚本仅显示说明；使用 `-Launch` 才创建新进程。日常使用可以改用前述画布直接启动或桌面快捷方式，不需要手打命令。既有实例不被停止，后台辅助进程也不会被当成主程序启动。
- “清除新进程代理环境”只清理该子进程的代理变量，并不代表它不再使用系统代理、私有配置或 TUN。脚本导出可指定 HTTP 环境，需该软件支持；SOCKS 环境导出仅对 `curl.exe` / `git.exe` 开放。**默认应用画布只支持本机 HTTP 入口**。受保护应用没有这些启动配置入口。
- 连接证据可说明观察到的 TCP 下一跳，不能仅凭本地代理端口或目标 IP 判断最终节点、真实下载或 UDP/QUIC 是否走代理。

需要编辑分流方案时切到 **路由设计**；两个视图共享同一份工作台，切换不会重置未保存草稿。

## 看懂高级分流图

从 **高级中继规则** 进入后，先看软件卡片里的 **这些网站**：这里显示具体网站及匹配范围，例如“steamcontent.com 及其子域名”，右边说明走普通网络还是代理。点击网站文字即可定位到右侧对应设置，不再用“域名规则 1”代替具体内容。上面的网站都不符合时，才采用最后一行 **其他网站** 的设置；没有网站例外时显示 **所有网站**。

右侧会用一句话解释当前设置。`example.com` 只匹配网站本身；`*.example.com` 匹配它的子域名，不包括本身。两项同时填写时，界面合并解释，原有匹配数据保持不变。规则从上往下检查，首个符合的规则决定连接方式；`*` 已包含所有网站，后面的规则不会命中。

卡片和右侧分别显示 **① 规则、② 分流入口、③ 软件实际使用**。入口未启动时只是方案；实线仅表示入口已加载当前规则。入口启动后修改图，仍在运行的入口继续使用上次规则，界面会提示“改动尚未应用”，需停止后重新预览并启动。服务失联时显示未同步。软件接入保持“待验证”，不会把检测请求或中继监听当成 Steam 已经使用代理的证据。

入口启动后，右侧可复制它的地址，也可直接前往 **应用连接**：把目标软件连到对应 **本地分流**，保存并启动，再到目标软件中验证实际操作。

## 先看这四种状态

| 状态 | 能说明什么 |
| --- | --- |
| 设计方案 | 你希望通道走向哪个出口，尚未控制真实应用 |
| 本机已观察 | 检测时读到了哪些设置、进程、端口、接口或变化 |
| 中继端口已监听 | 本工具的环回入口运行中，可接收显式发送到这里的请求 |
| 真实应用未验证 | 当前没有足够证据确认真实下载、远程会话或持续连接 |

代理端口存在、进程运行或配置声明了协议，都不等于出口可用。检测界面保留“观察”“未知”“待验证”，探测成功不会将任意应用标记为正常。

## 检测并理解当前机器

启动后点击 **自动检测**。底部 **分层证据** 展示 WinINet、WinHTTP、工作台进程环境、用户/机器环境、代理配置线索、接口和 hosts / DNS。工作台进程的环境变量不代表 Codex 或其他进程的实际环境。

代理候选库只显示识别出的代理线索；所有 TCP / UDP 监听另计总数，常见端口号不会被直接当成协议证明。**本机变化** 会列出前后值，写入者未知时仍显示未知。

UU 运行时会出现独立的加速层和上下文节点，可见进程、监听数、hosts 线索与共存发现。工作台无法读取的 UU 选项仍需你在 UU 界面核对；检测到 hosts 变化也不据此推断写入者。

## 接一个应用通道

先切换到 **路由设计**。

1. 从左侧应用库选择应用。Steam、WoWS 和 RustDesk 有初始模板；Codex、UU、hosts / DNS 是上下文或保护节点。
2. 点击应用通道右侧圆点，再点击出口左侧圆点。虚线代表设计连接。
3. 在右侧编辑通道名称、默认出口和域名规则。规则从上到下首次匹配，未命中时使用默认出口。规则可填精确域名、IP、`*.example.com` 或 `*`；`*.example.com` 不包含根域名 `example.com`。
4. **本地入口端口** 填 `0` 由系统分配；需要应用长期保留同一个代理地址时可指定空闲固定端口。启动返回的端口才是实际值。
5. **保存方案** 只保存设计。点击 **预览影响** 阅读问题、限制和映射数量，再点击 **只启动本地入口**。

启动后，底部 **运行入口** 与通道属性可复制实际 `http://127.0.0.1:端口` 代理 URL。只有应用明确采用这个入口，请求才会经过本中继。若应用没有代理配置或忽略系统代理，画线本身不能控制它。

运行中修改草稿，不会悄悄更改已有连接或运行规则。完成编辑后停止入口，重新预览、启动。停止会中断经过本入口的连接。

默认画布聚焦当前通道与相关出口，以至少 70% 缩放显示，必要时可上下平移。点击 **全部节点** 或按 `0` 才进入整体总览；**聚焦通道** 返回可读的当前通道视图。窗口宽度不超过 1000 像素时，应用库变成图标栏，属性改为可开关抽屉，画布上方可展开应用库、打开属性。空格拖动画布，Ctrl + 滚轮缩放；选中节点后可用 Alt + 方向键移动。手动缩放后，轮询和窗口调整不会自动缩回总览。

## 用探测确认实际路径

**出口属性 → 有界连通探测** 使用当前草稿中的出口，适合核对一个 HTTP / SOCKS5 上游是否可达，不代表应用已经接入。

**通道属性 → 验证运行中的通道** 使用已经启动的实际入口、规则和解析映射。这里采用运行配置，未应用草稿不会影响结果。输入一个你准备访问的 HTTP(S) URL，或选择 WebSocket 升级握手后输入相应 URL，再探测。

结果逐层显示 DNS / TCP / TLS / HTTP / WebSocket 等证据。活动中的 **路径已建立 / 进行中** 只证明当前 TCP 路径已建立；连接结束、字节数和真实应用表现要继续观察。HTTPS 隧道不会被解密。

## 应用实例：将通用操作用于当前软件

以下将同一四步流程用于已有适配和软件案例。案例对应的通用功能、证据和反例见 [应用实例与验收案例](应用实例与验收案例.md)，不作为软件专用功能待办。

### 独立后台应用示例：Hermes

1. 在 **路由设计 → 应用连接** 选择已安装的 **Hermes**。自动发现使用当前 Windows 用户目录，不写死盘符。`Hermes-Setup.exe` 会标为安装器；`bin/hermes.exe` 是 CLI，不能代替桌面主程序。
2. 点 **检查此软件** 或 **诊断此软件**。检查会分开说明桌面窗口、模型请求后台与代理变量；没有合适的公开地址时留空即可。根据证据选择已识别的 v2rayN 等 HTTP 入口，再点 **保存连接设置**。
3. 点 **预览应用步骤**。如果提示旧窗口环境不一致，从 Hermes 菜单正常退出后重新预览。只关闭窗口右上角可能仍留在托盘。旧窗口不能原地换环境，也可能自动重建旧环境后台，因此需要这一步。
4. 核对影响后点 **确认并应用**。需要后台重启时使用 Hermes 官方 `-p default gateway restart --detach`，不带强制中断参数。进行中任务、后台身份或活动状态不可信时拒绝操作。默认后台承载的多个 profile 会短暂重连；不更改模型、身份、凭据、聊天或 profile 配置。
5. 点 **验证已保存设置**，然后在原聊天重试模型，按实际结果选择 **原软件已正常** 或 **仍然失败**。后台就绪、环境一致或工作台访问成功都不能证明模型已回复；profile 私有覆盖仍可能影响结果。最后创建桌面快捷方式，以后复用保存设置。

当前支持 Windows 原生 checkout 桌面布局。自定义外置数据目录、其他后台入口格式和不支持的进程架构会显示限制。HTTP 方式为本机和私网 IP 添加绕过项；局域网主机名不自动视为私网。检查只保留代理变量及 Hermes 数据目录身份白名单，命令行只用于核对指定后台，不保存完整进程环境或认证内容。


**Hermes 重启后又掉线：** 在画布选择已安装的 Hermes，点 **检查此软件**，区分后台未运行、身份未知、代理环境不一致。需要应用时按预览操作；后台未知或仍有任务时不要反复重启。即使环境一致，也不能认定网关、订阅或模型正常。当前没有持续监测或掉线根因诊断；已知的 `%LOCALAPPDATA%\hermes\logs` 目录需自行在资源管理器核对，软件尚未专门适配该日志目录。此路径是默认位置，外置 home 不应照抄。

**VRChat 与 UU/代理共存：** 先添加/选择 VRChat，查看应用详情的连接快照，在画布 **检查此软件** 读取所选进程的代理变量；再核对实际启动它的 Steam 或启动器。“分层证据”中的用户/机器变量是持久设置，“检查此软件”中的变量是运行进程的值，两者可能不同。仅在有残留代理证据且希望清除该启动环境时，才选择 **不使用环境代理**、保存并从工作台重新启动相关启动器；旧实例需正常退出，原来的桌面启动方式不会自动采用这项设置。VRChat 若由 Steam 拉起，单独给 VRChat 保存设置不能改写已经运行的 Steam。没有发现变量时不要套用旧机修复；UU 专用线路、TUN、DNS、内容下载及游戏日志还需另查。当前没有专用自动归因/一键修复，最后仍需原游戏世界和头像加载验证。

**Steam 社区走代理、下载走直连：** 使用现有代理作为默认出口，为已确认的下载域名添加直连规则。模板中的域名是起点，不能覆盖全部 CDN。实际请求经过本入口后，活动记录会显示域名、通道和命中出口；点击 **添加直连规则** 只加入草稿，核对后重新启动配置。若没有 Steam 事件，先核对 Steam 是否真的采用了本入口。

**WoWS 三端更新直连：** 三个通道分别配置。先在游戏资源切换器里完成更新隔离，再自行打开官方客户端；这里既不启动下载，也不更改游戏文件。仍须验证客户端是否采用入口、实际出口与下载流量。

**RustDesk 与 TUN 共存：** TCP 直连、绑定接口、代理 CONNECT 和真实 RustDesk 会话是不同证据。DIRECT 仍可能进入默认 TUN 路由，本工具不自动改排除路由或验证 UDP 打洞。能访问一个测试端口，不足以证明远程会话可用。

**hosts 在代理下看似失效：** 选择 hosts / DNS 节点，比较系统解析与匹配的 hosts 线索。上游代理可能独立解析域名。需要固定本中继的目标地址时，添加“精确域名 → 字面 IP”映射，随后预览并重新启动。映射不接受 URL 或通配符，不修改系统 hosts，并保留原 HTTP Host / TLS 域名。

## 可回退的系统接入

只有明确需要让采用 WinINet 的应用一起使用某个运行入口时，才展开右侧 **高级 · 系统接入**：

1. 选择已运行通道，点击 **预览系统接入**。
2. 阅读原设置、新设置、后端允许条件、域名规则和 DNS 映射。它们影响所有采用这个系统入口的应用，无法按进程区分；Codex 保护节点也不能阻止依赖系统代理的新连接受到此项显式变更影响。
3. 后端允许后勾选范围确认，再点击 **应用并观察，未确认会回退**。
4. 在 60 秒内实际检查连接。连接正常可点 **连接正常，确认保留**；也可立即 **恢复原系统代理**。未确认、停止或正常退出会请求恢复本工具的设置。

如果其他软件在此期间改了系统代理，界面会提示冲突或恢复失败，保留备份和入口以供处理。不要靠连续点击或直接杀后台解决冲突；先核对当前系统代理及提示。回退保护不是强行覆盖其他程序设置的承诺。

## 草稿、导入导出与退出

浏览器自动保留草稿。重新打开后，若草稿与服务器方案不同，显示 **已恢复未保存草稿**，不会静默覆盖。**恢复服务器方案** 是明确操作，可用 Ctrl + Z 撤销本次替换。

方案 JSON 可导入、导出；导出使用当前草稿，无需先保存。认证、订阅和节点密钥不属于方案。**导出脱敏诊断** 提供后端脱敏的状态与历史用于排查。

关闭网页后，中继和后台仍运行。右上角 **退出后台** 会请求恢复系统接入、停止本地入口并退出服务；发生恢复冲突时按错误提示处理。它不会退出 v2rayN、UU、Codex 或游戏客户端。


## 找不到代理卡片或网络工具拖不进画布

0.5.1 起，左下角所有已识别网络工具都支持点击显示、键盘选择和拖入。点击会把相应卡片移到视野内，拖动只改变画布位置，不保存或应用连接。

如果 v2rayN 卡片只有“TCP 端口 / xray.exe”，表示已发现监听但还没确认 HTTP 协议。点击该工具，在右侧选“检测代理入口”。成功后出现可接线的 HTTP 卡片，再把 Hermes 等软件连接到它并保存。没有发现监听时先打开代理软件，再点右上角“自动检测”。纯 SOCKS 入口需要在代理软件中另启用 HTTP 或混合入口；不要直接将专用端口当作 HTTP。

检测采用本机临时挑战服务，不访问互联网、不切系统代理。它确认本次 HTTP CONNECT 转发能力，不代表目标网站或模型已经成功。代理重启、端口或归属变化后需要重新检测；本次协议确认不跨 FlowDesk 进程持久保存。UU、aTrust、ZeroTier 可以显示在画布，但其观察卡片不能作为应用代理出口。

更新独立 EXE 时，先在旧页面右上角点“退出后台”，再运行新版本并刷新网页，以免重复启动复用旧后台。

## 检查入口各自能回答什么

| 入口 | 当前能检查的内容 |
| --- | --- |
| 自动检测 / 分层证据 | 系统与本机网络设置、进程/端口等快照；不自动修复 |
| 网络工具 → 检测代理入口 | 已观察的本机监听是否能执行本机 HTTP CONNECT 转发；不测外网 |
| 软件 → 检查此软件 | 所选进程及已适配后台的身份、代理环境；不读完整请求 |
| 软件 → 诊断此软件 | 地址留空只检查软件；填写后对照工作台访问路径，给出建议与下一步，不自动应用 |
| 软件 → 预览应用步骤 | 预览已保存设置的动作和限制；确认后才执行，状态变化要求重新预览 |
| 软件 → 验证已保存设置 | 重查进程；有地址时检查已保存路径；原软件结果由用户单独反馈 |
| 应用与设置 → 日志与配置 | 已知候选位置、存在的目录、有限脱敏日志尾部；不自动定位所有日志或持续跟踪 |

旧“连接诊断”向导保留在代码中，但主导航入口隐藏，旧接口也不能直接启动软件。当前标准入口为画布内四步流程；日志时间线、持续观察与请求分析等缺口和验收要求见 [需求核查与待办](需求核查与待办.md)。
