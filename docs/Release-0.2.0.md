# 0.2.0 · 从接线图补齐应用与设置总览

日期：2026-10-24。

此前入口以路由画布为中心，用户需要先理解中继、通道和出口，才能寻找某个软件的设置。本版默认从软件开始：查看设置来源、观察到的连接、日志与配置位置，再按该软件支持的方式处理。原路由设计、系统接入预览及恢复机制保留。

## 已实现

- 应用搜索、运行筛选，以及内置应用以外的正在联网进程；采集有界，不读取任意进程参数或私有环境块。
- 系统代理/PAC、WinHTTP、用户和机器环境变量、应用设置、TUN/路由分层展示，显示观察时间和旧快照状态。
- TCP 下一跳与代理候选端口关联；非回环目的地址只保留摘要，代理核心远端节点细节继续隐藏。没有证据时不宣称直连、具体节点或 UDP 路径。
- 真实存在与候选日志/配置路径分别显示；资源 ID 与应用绑定，日志有界读取并脱敏，配置仅定位。重解析点、未知硬链接、轮转文件及跨应用访问会拒绝。
- 预览和下载新进程环境脚本；仅为新子进程清理或设置代理变量。默认不执行，目标需要 `-Launch` 才启动。保护 Codex、代理核心及加速器；仅有辅助进程时不把它当主程序启动。
- 诊断导出包含应用目录及证据摘要，日志正文不会自动混入导出。

## 验证

最终 EXE 已完成复测，142 项单元测试、12 项浏览器 UI 检查和 20 项设置文字展示场景通过。最终正式 EXE 的设置卡片另已在实际浏览器中查看，系统代理、WinHTTP 与环境变量以可读文字展示。本次复测构建的 SHA-256 为：

```text

```

- 本机只读发现：验证设置、进程、监听端口、TCP 对端及日志/配置位置的读取与展示。结果说明采集时观察到了什么；配置值和候选入口不能证明目标软件采用了该代理或最终出口。
- 本地中继测试：结论仅覆盖测试客户端实际送入本工具入口的请求，以及对应的 TCP 中继行为。入口正常、规则匹配和中继测试通过，不等于其他软件已经接入。
- 任意应用强制路由：本版没有验证或实现对任意 Windows 应用的透明强制接管。现有进程是否采用环境变量、UDP/QUIC 路径、最终出口和真实应用完整会话，需要各自的运行证据，不能从单元测试、UI 检查或本地 TCP 中继结果推定。

EXE 在包含中文与空格的临时目录中通过启动、配置保存与重启、重复启动复用、网页资源一致性、只读发现、保护应用、守护恢复入口及正常退出检查。测试子进程 PATH 中不含 Python。

打包入口现在先写候选目录，等待构建退出，再检查 PKG 归档边界、压缩成员和文件散列并执行实际启动测试。正式 EXE 正在运行时保留原文件，验证通过且文件可替换时才原子发布。本次已实际验证“运行中的正式 EXE 保留”分支，再正常退出未启用中继/系统接入的工作台，换入验证后的 EXE。

## 迁移

项目支持把源码版与独立 EXE 版的数据统一到项目目录。迁移时应分别备份方案、历史和快照并核对散列，选择需要保留的保存方案，保留原数据目录，不复制进程锁或系统接入事务。

项目标记 `flowdesk-project.json` 让源码启动、项目启动脚本和项目 `dist` 中的 EXE 使用同一份 `.local`。单独移出项目的 EXE 保持原有 AppData 默认行为，也可指定 `--data-root`。

更换正在使用的 EXE 前需正常退出工作台；只有确认没有运行中继、没有接管系统代理时，才能把替换操作当作对网络无影响的升级。此版本当时仅在本地验证，随后与 0.2.1 一并发布。

本机验收包括保存方案一致性、WinINet/WinHTTP/代理环境变量前后指纹以及受保护进程保留检查。含具体机器信息的备份和详细验收记录留在被 Git 忽略的 `artifacts/`。

## 适用边界

本版是设置与诊断工作台，不能强制接管任意 Windows 程序。某些软件需要自身设置、逐进程转发工具或 TUN 引擎；环境脚本是否生效取决于软件。实际 TCP 对端、进入中继、命中内核规则、最终出口和真实会话是不同证据层。

调查结果及官方资料见 [工具调查](工具调查-20261024.txt)。按程序控制已有成熟工具可选，本版没有安装驱动或自动切换到另一套代理引擎。
