# 0.3.0 · 识别本机网络工具，按问题引导处理

此前用户需要在设置、探测、启动配置和路由设计之间自行组织排查。本版默认从“哪个软件连不上”开始：选择软件，粘贴报错或失败地址，对照检测后获得具体建议，再直接为目标软件准备并使用代理环境。

## 本机识别

- 识别已安装记录、运行进程、相关服务、网卡和监听端口。补充 UU 的辅助进程、aTrust 和 ZeroTier 的进程/服务/网卡关联。
- 根据实际父子进程关系，把 v2rayN 启动的 Xray 等核心及端口归入管理客户端。
- 只有配置声明或当前系统 HTTP 代理与实际监听匹配的本机入口才进入对照检测。不会按常见端口猜协议。
- UU、aTrust 和 ZeroTier 的专用监听只作为加速、隧道或组网依据，不能作为任意应用的 HTTP/SOCKS 代理。未运行的便携软件仍可能无法自动发现。

## 引导式处理

从错误文字提取地址，比较普通连接与最多三个本地代理入口，明确给出下一步。可区分代理路径可达、普通连接可达、HTTP 权限/地址响应、仅 SOCKS 可达和没有可用路径。

建议 HTTP 环境方式时，用户核对方案、关闭目标软件后可直接点“按方案启动”，无需先学习代理变量或运行脚本；手动下载启动文件仍作为可选方式。只为该新进程设置代理环境，拒绝结束现有实例，保留网络基础组件与 Codex 的保护。是否采用代理仍取决于目标软件；需要用户重试原操作并确认结果。

目标地址中的凭据、查询参数与片段会被拒绝；错误文字不会存入诊断历史。启动操作必须关联有效检测记录、原目标程序与可用 HTTP 入口。系统代理、TUN、路由、hosts、持久环境和既有进程不由此流程修改。

## 验收范围

使用合成数据覆盖管理客户端与核心归属、服务/网卡识别、私有端口排除、无端口猜测、HTTP 响应含义、保护应用、过期与变更记录拒绝、私有子进程环境及现有实例拒绝。

实际本机识别出 v2rayN/Xray、UU、aTrust、ZeroTier。针对 Hermes 官方安装脚本地址的真实检测复现普通路径 TLS 失败、代理路径 HTTP 200，并生成匹配入口的方案；没有代替用户重跑安装。

前端使用实际事件代码配合合成 DOM/API 做回归。本次本地浏览器自动化被设置禁用，因此未进行浏览器视觉验收；不得把事件与 HTTP 接口检查称为完整浏览器验收。

181 项 Python 测试、9 项引导页事件检查和 11 项手动软件清单事件回归通过。Windows 独立 EXE 在中文与空格路径通过启动、网页资源一致性、引导接口与真实环回目标检测、清单持久化、本地中继、守护恢复入口和正常退出检查。
