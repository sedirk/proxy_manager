# FlowDesk 0.6.0 · 通用应用连接流程

此前软件检查、目标地址诊断和启动设置分散在不同入口，独立后台的处理直接依赖某个软件名称。本版把已有能力接入同一流程，软件差异集中在内置适配器中。

- 在路由图选择软件后，按“检查 → 诊断 → 预览应用 → 验证”处理。诊断地址可留空；填写后比较普通连接与已识别代理入口，建议只改变连线草稿。
- 普通应用、Chrome/Edge 和已有独立后台适配共用检查、影响预览、应用条件与复测逻辑。未知软件保留普通进程环境路径，不假定能管理它的后台或私有代理。
- 保存与应用分开。所有画布启动都先显示具体步骤，再由“确认并应用”执行。保留旧窗口、后台身份、进行中任务和并发操作检查。
- 验证核对已保存设置；填写目标地址时只探测该路径。进程环境一致、工作台 HEAD 请求通过与原软件操作成功分别展示。用户可记录“原软件已正常”或“仍然失败”，检测成功不会自动覆盖失败反馈。
- 设置、地址或应用操作变化后，旧证据失效。应用部分失败也不继续展示以前的成功结果；过期预览和不匹配反馈均拒绝使用。
- “查看此软件的设置与日志”直接定位既有应用详情，桌面快捷方式继续读取最新保存的设置。
- 窄屏使用“软件与工具”抽屉和可关闭的属性抽屉，避免卡片文字挤成竖排；画布随窗口尺寸适配，保留节点位置。“应用与设置”在窄屏上下排列，宽屏保持三栏。

本次只完善已实现能力的共用流程。Fiddler 式抓包、任意进程强制接管、持续健康监控、通用日志自动发现与跨机路径自动重绑定仍未交付。

## 使用

退出旧版后台后运行新版 EXE，原保存数据保留。选择软件，先检查和诊断，再选择连接方式、保存并预览应用。最后验证设置，回到原软件完成原操作，再记录实际结果。以后可用“创建桌面快捷方式”减少重复操作。

## 接口兼容

`POST /api/app-routes/launch` 对普通软件同样要求 `prepare-launch` 返回的单次票据。旧 `/api/troubleshoot/launch` 拒绝直接启动，需改用保存、预览和确认流程。新增 `app-routes/diagnose`、`verify`、`feedback`；仍使用本机服务原有会话与来源校验。

## 验证范围

后端使用普通应用、浏览器、已知与不支持的安装布局以及第二种合成后台适配样例；界面使用合成事件与隔离浏览器样例。测试不会修改系统代理、TUN、防火墙或启停真实目标软件。隔离样例不代表另一台电脑、真实模型回复、游戏下载或长期会话已经验收。

248 项 Python 测试、88 项界面逻辑检查（应用流程 60、高级分流 8、软件清单 11、旧向导 9）通过。实际浏览器验收覆盖 420、643 和 1366 像素宽度，隔离流程覆盖诊断、保存、预览、模拟应用、验证及用户反馈。

中文与空格路径、无 Python PATH 的 Windows EXE 验收通过，包含嵌入包完整性、四步 API、预览保护、证据失效、真实回环中继与正常退出。本机运行的 0.6.0 已核对资源和成品散列；保存数据、系统代理、WinHTTP、持久代理环境及受保护进程保持不变。
