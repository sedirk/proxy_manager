# 流向 · 本机代理工作台

在“路由设计”画布中，把软件连接到识别出的代理入口或默认连接方式，再直接保存该软件的连接设置并启动。设置来源与日志位于“应用与设置”，复杂域名分流保留为“高级中继规则”。界面和后端均在本机运行，无 npm 运行依赖。

当前版本为 **0.5.0**。识别 v2rayN/Xray、UU、aTrust、ZeroTier 等软件及其进程、服务、网卡与端口，区分可以使用的应用代理入口和加速/隧道专用端口。调查与产品边界见 [工具调查](docs/工具调查-20261024.txt)。

## 打开工作台

**在当前项目使用：** 双击 **启动代理工作台.cmd**（旧名称“启动代理接线台.cmd”仍可用），优先使用 `dist/FlowDesk.exe`，**不需要安装 Python**。源代码、前端、测试、构建和当前保存方案统一位于本项目。项目标记 `flowdesk-project.json` 使项目内 EXE 与源码共用 `.local`，直接打开项目内 EXE 也使用同一方案。

**单独携带 EXE：** 将 EXE 移出项目、没有项目标记时，数据默认保存在 `%LOCALAPPDATA%\FlowDesk\.local`，也可用 `--data-root` 明确选择。独立 EXE 与源码包见 [Releases](https://github.com/sedirk/proxy_manager/releases/latest)。

**从源码运行：** Windows 安装 Python 3.11 或更新版本后运行下列命令。默认复用上次页面端口，端口被其他程序占用时才重新分配。重复打开会复用同一服务。

也可在项目目录运行：

```powershell
python run.py
```

首次检测读取系统代理、进程、监听端口、接口、路由、hosts 和 DNS 等线索。启动工作台不会自动接管应用或修改现有系统代理、TUN、路由、Codex、v2rayN 或 UU 设置。

## 日常使用

默认进入 **路由设计 → 应用连接**：从左侧把软件加入画布，点软件右侧输出圆点，再点代理入口左侧输入圆点。在右侧核对后点 **保存连接设置**，关闭目标软件，再点 **按此设置启动**。右侧下拉框与画布连线表示同一项设置；连线显示“待保存”或“设置已保存”。

保存的是该软件从工作台启动时的连接方式，重启工作台仍保留。Chrome/Edge 使用显式代理参数，其他软件使用新进程代理环境并需要软件支持。已有运行实例保留原设置。没有识别到的软件可点 **添加其他软件** 选择主程序。

软件属性中的 **检查此软件** 会按需读取所选进程的代理白名单，解释保存设置与实际进程是否一致。保存后可 **创建桌面快捷方式**：以后直接双击，使用最新保存的连接设置，无需打开终端或手输 `-Launch`。保留 FlowDesk 所在位置；每台电脑各自选择程序和本机代理入口，不复制另一台的端口与绝对路径。

**Hermes 使用模型时：** 选择已安装的 **Hermes**，不是 `Hermes-Setup.exe`。连到识别出的 v2rayN HTTP 入口、保存后点 **应用并打开**。如果旧窗口环境不一致，先从 Hermes 菜单退出窗口，再应用。需要重启独立后台时显示影响范围，确认后使用官方命令并保留进行中任务保护；承载在同一后台的 profile 会短暂重连。后台 ready 与代理环境一致会分别核对，模型真实回复仍需在 Hermes 重试。本机和私网 IP 绕过代理，适合以私网 IP 访问的 Qwen；profile 私有代理覆盖及局域网主机名仍需单独核对。当前适配支持 Windows 原生 checkout 桌面安装，外置 home、无法确认身份或不支持的后台格式会明确拒绝自动重配。

HTTP 连接已包含 Electron 下载器代理兼容，覆盖新版及使用 global-agent 的旧版下载器；“按此设置启动”和导出脚本使用同一套配置。升级工作台后，已有保存连接无需重建，关闭目标软件后从工作台重新启动即可应用。已经运行的安装器及其子进程需要正常退出后重开。选择“不使用环境代理”会清理这些附加变量，“沿用默认设置”则保留继承环境。

需要查看详细设置或设计中继规则时：

1. 在 **应用与设置** 点击 **自动检测**，搜索软件。找不到时，在 **本机软件** 标题旁点击 **添加软件**，浏览选择 `.exe` 或粘贴完整路径，可填写显示名称。手动登记会保留到下次启动，同一程序路径会合并；添加本身不会运行软件或更改代理。
2. 查看软件的 **设置来源**：系统代理/PAC、WinHTTP、环境变量、应用私有设置及 TUN 分开解释。观察到的 TCP 下一跳不等于最终出口；未验证会明确标注。
3. 在 **日志与配置** 定位实际存在的文件，打开所在目录或查看脱敏日志尾部。候选路径和已发现位置分别显示；配置内容不会作为日志读取。
4. 有明确程序路径时，可预览、下载 **新进程环境脚本**。脚本默认只显示说明，使用 `-Launch` 才启动目标。它只控制新子进程环境，不重配当前进程，也不保证忽略环境变量的软件服从代理。Codex、代理核心和加速器受保护。
5. 需要域名分流时，在 **路由设计** 点击 **高级中继规则**，接好通道、预览并启动本地入口，再把支持代理的应用显式接入。原中继方案与应用启动连接设置独立保存。

高级分流图直接列出 **这些网站 → 连接方式** 和 **其他网站 → 连接方式**。例如 `steamcontent.com` 与 `*.steamcontent.com` 会合并解释为“steamcontent.com 及其子域名”；点击网站文字可打开对应设置。规则按从上往下的顺序检查，最后处理其他网站。**规则已保存、分流入口是否启动、软件实际使用是否验证** 分开显示：连线或中继监听都不证明 Steam 等目标软件已经采用该设置。运行期间修改规则，会明确提示当前图尚未应用。

**设计接线、本机观察、入口监听、真实应用验证分别展示。** 画一条线不会给不支持代理的任意进程注入网络控制。Codex 是保留当前连接的保护节点。

高级 **系统接入** 会另行预览当前用户 WinINet 变更；它影响所有采用该设置的应用，包含域名规则和解析映射。后端允许、用户确认范围后才应用，60 秒内未确认会尝试恢复。检测到第三方改动时保留冲突信息，不强行覆盖。

关闭网页不会退出后台。使用右上角 **退出后台** 请求停止中继并恢复本工具的系统接入；如存在恢复冲突，处理提示后再退出。

## 当前边界

- 直连按系统路由建立 TCP 连接，仍可能经过 TUN；指定接口也不证明真实应用或 UDP 已绕过 TUN。
- 本中继不做 HTTPS 解密，不支持 SOCKS UDP、QUIC 或需要认证的上游代理。
- HTTP 200、TLS 成功或 WebSocket 升级握手只证明对应探测层，不证明完整下载、长连接稳定或 RustDesk 远程会话。
- UU 作为独立加速层观察。私有监听口不会作为 HTTP 出口；截图中的选项、驱动重定向和游戏会话需手动核对。
- DNS 映射只作用于经过本中继的精确域名，保留原 HTTP Host / TLS 域名，不修改系统 hosts。
- WoWS 更新前仍需在资源切换器中隔离共享文件；接线台不负责游戏文件管理。

项目内源码与 EXE 共用 `.local`；浏览器保留未保存草稿。手动软件清单存储在 `.local/custom-apps.json`，可在应用详情移除手动登记，不会删除程序文件。迁移数据位置时请先备份原目录。导出诊断包含应用目录与证据摘要，不自动包含日志正文；导入、保存、自动检测均不会启动网络入口。
